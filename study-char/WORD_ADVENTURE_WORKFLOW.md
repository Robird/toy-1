# 单词小冒险关卡批量制作指南

本指南用于持续扩充 `word-adventure.html` 的词汇关卡。新会话先读本文、实际代码和最近的批次记录，再执行制作。优先使用现成 emoji；没有合适图示时用中文含义和听音学习，必要的 SVG 可以另行补充。子 agent 并行整理词义、匹配图示和生成数据，主 agent 统一查重、审稿、验收和接入。

已实现完整大纲词库、短语拼写、中文提示和全局难度参数；通用 SVG 注册表仍未实现。后续每次完成制作，都要更新批次记录和本文的项目状态，方便下一个会话接续。

## 新会话启动提示

用户可以直接复制下面这段话。调整数量或主题即可重复使用。

> 请读取 WORD_ADVENTURE_WORKFLOW.md，检查 word-adventure.html 和已有批次记录，参考我指定的词汇文件补齐未收录条目。使用 gpt-6-luna 子 agent 并行整理释义和图示；有合适 emoji 就显示，没有则用中文与听音学习，包含抽象词和短语。难度使用页面级配置，不在每条词汇里重复设置。按指南完成审稿、预览、验收和接入，保留单 HTML 可直接打开的使用方式，更新批次记录。词表已经全部收录时说明覆盖情况，不重复添加。请实际完成制作。

这段提示明确授权并行制作、页面修改和验收。执行时仍以用户在当前会话提出的数量、主题、风格及其他约束为准；不需要再逐词询问普通选词或绘制细节。

## 开始一批制作

1. 读取适用的 `AGENTS.md`、本文、游戏代码、素材目录及最近的批次记录。检查现有工作区改动，保留用户正在进行的工作。
2. 从实际 `WORD_POOL` 或已建立的正式数据源提取单词、ID 和插画引用。文档中的旧清单不能替代代码。
3. 查找未完成批次：先区分已接入、已验收但未接入、待验收、待返工和未开始，复用可用成果。未完成工作与本轮新词数量分别计数，避免重复计入。
4. 确定本批数量、词义和文件负责人，将任务清单写入新的或正在续做的批次记录。
5. 将候选词分成 emoji 和中文提示两类，均可直接接入。只有本批明确需要新增 SVG 时，才执行可选的通用插画接口改造。

用户要求补齐指定词表时，以全部未收录条目为范围，不能只做 12 条。用户明确要求小批新增但未指定数量时，建议 12 条。没有未收录条目时报告已全覆盖，不造新词凑数。下一批从 `batch-002` 开始；续做原批次时沿用原编号。

## 选词和关卡数据

按用户指定词表确定范围。完整覆盖时包含名词、动词、形容词、介词、代词、称谓和短语；不能因为没有图示或单词较长而遗漏。自主选词的小批任务可以优先选择具体名词和短词。

- 先查重，再选词。大小写不同不算新词；同词不同难度也不算新增词汇。
- 明确义项：如 BAT 表示蝙蝠还是球棒，必须在派发前确定。中文含义和插画表达同一对象。
- 不通过增加罕见词或大量近义词凑数量。候选词不足时从其他适合的主题补充。
- 图示不泄露目标英文拼写；中文模式可以显示中文含义。
- ID 唯一且稳定。沿用 `pig-01` 这样的风格，实际分配前检查冲突。
- 词条不包含 `distractorCount` 或 `showSpelling`，统一从页面级 `GAME_OPTIONS` 读取。

当前数据格式示例：

```js
{ id: 'cat-01', word: 'CAT', meaning: '猫', illustration: '🐱' }
```

新增 emoji 关卡可以直接沿用现有格式：

```js
{ id: 'pig-01', word: 'PIG', meaning: '猪', illustration: '🐷' }
```

无合适图示的词和短语使用以下格式：

```js
{ id: 'about-01', word: 'ABOUT', meaning: '关于；大约', illustration: '' }
{ id: 'ice-cream-01', word: 'ICE CREAM', meaning: '冰淇淋', illustration: '🍦' }
{ id: 'pe-01', word: 'PE', meaning: '体育；体育课', illustration: '', display: 'PE', speech: 'P E' }
```

`display` 是可选的规范大小写，例如 `I`、`China`；`speech` 是可选的朗读文本，例如 `Mister`、`T V`。通常省略这些字段。输入仍使用大写字母，短语中的空格不需要键入。

## 全局难度参数

直接修改页面脚本开头的 `DEFAULT_GAME_OPTIONS` 可以改变默认难度。也可以在打开页面时传入 URL 参数：

```text
word-adventure.html?distractorCount=4&showSpelling=false
```

`distractorCount` 接受 0 到 26 的整数，实际干扰字母数受剩余字母数限制；无效值回退默认值 2。`showSpelling` 接受 `true` 或 `false`，无效值回退默认值 `true`。隐藏拼写时，未填写的格子和说明文案不显示目标英文，听音仍读单词及逐字母拼写。

参数作用于整个本次页面会话。页面是静态 HTML，配置入口是页面级默认值和 URL 参数，不需要服务端环境变量或为每个词重复配置。

需要新增 SVG 时，再考虑增加 `artKey` 引用插画。它是待实现的扩展字段，不能仅加字段就认为页面会显示 SVG。同一个词的多个难度关卡共用一张 SVG，避免重复绘图。

当前等概率抽取的是记录。若以后为同一单词增加多条难度记录，该词的出现概率会随记录数增加；调整抽取策略需要明确需求。

## 优先选择 emoji

用户已明确：有现成 emoji 可用时优先使用，以快速扩充关卡。不要为风格统一而把已有可用 emoji 批量重画成 SVG。

1. 选词时同时匹配 emoji，例如 PIG 🐷、FOX 🦊、BEE 🐝、ANT 🐜、APPLE 🍎、BOOK 📖。这些是候选示例，使用前仍须查重。
2. 图示要能直观表示目标义项。不要用邻近物体或泛化符号代替，例如用棒球表示球棒；有歧义时换一个词或图示。
3. 保留完整 emoji 序列，包括需要的变体选择符或连接符；不要假设每个 emoji 都只有一个字符，也不要截取首个字符。
4. 实际查看页面中的图示，检查是否显示为缺字方框、是否可辨认、是否被裁切。emoji 外观随系统和浏览器变化，不要求与猫 SVG 色板完全一致。
5. 没有可靠 emoji 时用 `illustration: ''`，通过中文与听音学习。完整覆盖任务必须保留该词；用户要求图示时再进入 SVG 补图队列。

emoji 和中文关卡不需要独立图片文件或 `artKey`。批次记录保存实际 `illustration` 字符串和匹配理由即可。保留现有猫 SVG；旧词补图不作为默认任务。第 1 批发现 Windows 将中国国旗显示为 CN，故 CHINA 使用中文模式；其他系统支持旗帜也不能假定目标设备一定支持。

## 需要 SVG 时建立通用插画接口

本节只在需要新增 SVG 时执行，使用 emoji 或中文提示的批次可以跳过。由主 agent 完成以下一次性工作，并记录最终接口名称和数据格式。

1. 将现有猫 SVG 保存为可维护的源素材，作为所有绘图任务的视觉参照。
2. 建立按 `artKey` 查询的插画注册表和统一插画容器，替换按猫 emoji 判断的 SVG 特例。
3. 同步调整 `validateLevel`，检查新增字段与素材引用；继续支持直接使用 emoji 的关卡。
4. 为通用插画保留响应式尺寸、无障碍名称及完成关卡时的动画。当前 CSS 针对 `.cat` 和 `.emoji`，新增容器或类名后需要同步处理。
5. SVG 随 HTML 内嵌，保证成品无需网络或本地服务器即可打开。

初期可由主 agent 将验收后的 SVG 接入 HTML 注册表。词量增长、手工同步开始容易出错时，再增加小构建脚本，将正式数据和独立 SVG 源文件生成到 HTML。使用脚本时明确源文件位置和生成命令，避免源文件与成品各改一份后产生分歧。

不要为了批量绘图引入后台、数据库或大型打包系统。源素材可以分文件维护，交付页面仍是单个 HTML。

## 必要 SVG 的插画规范

仅对用户需要补图的词使用本节。以现有猫为风格参考，使用可编辑的 SVG 基本形状和路径。该任务适合直接编写矢量素材，无需额外调用位图生成工具。

| 项目 | 约定 |
| --- | --- |
| 画布 | `viewBox="0 0 240 220"`，独立文件包含 SVG 命名空间 |
| 背景 | 透明；页面已有奶油色圆形背景，不在素材中重复绘制 |
| 构图 | 单个主体居中，保留约 12 px 边缘，主体占比与猫相近 |
| 轮廓 | 圆润、大色块，描边通常约 2.5 到 3 px，圆角连接和线帽 |
| 色彩 | 柔和暖色为主，保留对象的自然识别色 |
| 参考色板 | 奶油 `#f6dfb8`、浅棕 `#edc58d`、描边 `#bf8b53`、深色 `#4b493a` |
| 表情 | 动物可用点状眼睛和轻微腮红；物品不必全部拟人化 |
| 依赖 | 自包含，不引用外链图片、字体、脚本或 emoji 替代物 |
| 标识符 | 需要渐变或裁剪 ID 时，以素材键作前缀，避免内嵌后冲突 |
| 可辨识性 | 约 150 × 140 px 下仍能看清主体和关键特征 |

眼睛、阴影、线条和配色可以复用；不同对象要保留独有轮廓。猫狗、杯碗等易混淆对象不能仅换颜色。不要用大量微小细节换取复杂度，缩小后辨认对象更重要。

## 使用 spawn_agent 并行制作

创建本文的会话共有 4 个并发槽位，包含主 agent，因此适合主 agent 加 3 个 worker。新会话以实际工具和并发限制为准；只有较少槽位时减少 worker 数量。

普通小批按主题划分，每个 worker 提交约 4 到 6 条候选。完整词表按非空条目的顺序分段，不按原文件行号切段。第 1 批把 441 条分成 1 到 147、148 到 294、295 到 441 三段，worker 跳过已收录词。主 agent 最终比较完整词表与词库，确保没有缺词、跨段误读或重复。

按用户意见，emoji 匹配和释义整理可以使用 `gpt-6-luna`；本批已实际采用。指定模型时使用 `fork_turns: "none"`，在任务中给出完整的文件、范围、字段和分工。对子 agent 的产出仍要审稿，本批曾发现 HIS 被误写成 THIS、司机配成飞行员等问题。必要绘图任务沿用当前允许的模型设置。

确实需要绘图时，让有空位的 worker 先做 1 张样图；风格校准后再完成约 4 到 6 张的任务包，按复杂度调整。样图通过后计入任务包，不重复绘制。少量 SVG 可以与其他 worker 的 emoji 数据整理并行，不阻塞已验收的 emoji 关卡接入。

`spawn_agent` 可通过当前会话提供的 `collaboration.spawn_agent` 调用。首次派发示例：

```json
{
  "task_name": "word_candidates_a",
  "model": "gpt-6-luna",
  "fork_turns": "none",
  "message": "工作目录为项目根目录，请先读取 WORD_ADVENTURE_WORKFLOW.md、指定词表和 word-adventure.html。负责主 agent 分配的非空词条范围，跳过已有词。只写指定 worker 目录的 candidates.json，不修改主 HTML、其他 worker 文件或正式清单，不再派生 agent。每条包含 id、word、meaning、illustration；word 使用大写并保留词内空格，id 用小写连字符。难度不放进词条。emoji 无可靠匹配时 illustration 为空串，不漏抽象词和短语，不用邻近物体凑图。必要时包含正确的 display 和 speech。单独记录源范围及疑问，UTF8 无 BOM 写入，返回文件路径和摘要。"
}
```

实际使用时替换批次号、主题和负责人。候选文件可以采用 `{ "levels": [...], "notes": [...] }` 结构；只有 `levels` 中符合游戏数据规范的条目可供接入，未解决的条目在备注中列明。所有 worker 收到同一选词规范和已有单词清单。

不要为每个词反复创建新 agent。用 `collaboration.followup_task` 补派候选、修改图示或安排必要的绘图；返工交回原 worker。使用 `spawn_agent` 返回的实际任务标识作为 `target`：

```json
{
  "target": "word_candidates_a",
  "message": "请核对分配范围中的源词与候选数据，修正发现的误读和重复；不能遗漏原词条。不能直接表达词义的 emoji 置为空串。只修改原候选文件，返回变更摘要。"
}
```

SVG 任务要明确具体单词与义项、参考猫 SVG、统一画布和风格、指定唯一文件负责人。先交样图，收到后续指令再扩批。返工说明要具体，例如“长口鼻在缩略图中不明显，请突出轮廓”。发出返工任务后，主 agent 可以接入其他已验收条目。

调用工具时遵守当前允许的模型和上下文设置。若新会话没有 `spawn_agent` 或无法使用指定模型，说明实际限制并采用可用方式完成，不声称使用了不存在的工具或模型。

## 预览和接入

主 agent 收到候选数据或 SVG 后，将状态改为待验收。子 agent 汇报完成只表示已交稿。

1. 合并候选数据，检查单词、ID、中文义项和图示；跨 worker 去重，确认词条不含重复难度配置。完整覆盖时逐条对照源词，不能只对比总条数。
2. 生成批次预览页，在接近实际大小的图示旁显示单词和中文含义。SVG 批次增加猫参照和约 150 × 140 px 的缩略图。
3. 使用可用的浏览器、渲染或截图查看能力检查图示与词义一致、可辨认、无裁切；emoji 检查是否正常显示，SVG 额外检查风格协调及文件完整性。仅阅读字符或 SVG 代码不能记录成视觉验收通过。
4. emoji 和中文条目直接接入 `WORD_POOL`；SVG 条目通过后保存源素材并接入注册表。集成只使用游戏字段，不把候选备注放进正式关卡。
5. 按本轮授权做必要的游戏验收：图示或中文正确、空格不占字母格、重复字母能完成、听音文本与词义一致、积分及下一关正常、窄屏长词可用。检查全局难度的正常值、无效值和隐藏拼写模式。
6. 随机出题不能保证覆盖新词；验收时用预览页或临时的指定关卡方式逐个检查。临时调试入口不进入正式成品。

如果本会话缺少实际渲染能力，记录为待视觉验收，交付可打开的预览页并说明具体未确认项。不要把无法检查的项目写成已通过，也不要将未验收草稿登记为正式完成。

某张图失败不阻塞其他已验收词的接入。批次只有在计划项目都完成，或用户明确调整范围后，才能登记为完成；部分完成时逐词记录剩余工作。

## 批次记录模板

主 agent 在 `docs/word-adventure-batches/batch-NNN.md` 中记录实际进展。记录要随阶段更新，避免会话中断后无法判断哪些文件已接入。

```markdown
# 单词小冒险第 N 批制作记录

日期：YYYY-MM-DD

状态：制作中 / 部分完成 / 完成

用户要求：本批数量、主题和其他约束。

本批计划新增词数：
```
