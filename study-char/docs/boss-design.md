# 单词小冒险动态 Boss 设计方案

日期：2026 年 10 月 3 日。状态：已完成设计审查与三种题型实现，规则及真实浏览器回归通过；目标设备实际试听待家长确认。

用最近 100 道已结束题目的记录，动态选择孩子确实练习过的词，生成听音选图、部分拼写或完整拼写挑战。Boss 成功提供接下来 5 道普通题积分翻倍的能力，使“接触单词—回忆挑战—提升刷题收益—接触更多单词”形成循环。保留普通题的轻松体验、随机登场和显眼庆祝。

用户已追加授权按本文实现游戏。以下数值已作为集中配置的原型默认值落地，不是已经验证的儿童学习最优参数。

最小模型是：普通题完成后追加历史，遇敌时从历史取合法词，每词生成合法题型集合，随机选词与题型；首次独立答对授予 5 次双倍。历史适应近期接触内容，暂不做技能等级或逐词解锁。审查裁决见 [设计审查记录](boss-design-review.md)。

试玩后已实施 [控件自明性与误触保护方案](boss-controls-design.md)：固定图示与语音说明、单面板内选择后执行、退出直接普通题。打开求助与点图卡不结束挑战，另点大勾才学习或离开；取材与奖励规则继续由本文定义。理由见 [控件改进审查记录](boss-controls-design-review.md)。

## 需求与证据边界

| 来源 | 当前约束或决定 |
| --- | --- |
| 用户本轮决定 | 以最近答题历史动态取材，History 100 是可接受的近似；不用人工固定 4–6 词作为必需入口 |
| 用户本轮决定 | 加入听音选图和部分拼写，保留听音完整拼写 |
| 用户补充决定 | 选图按完整 emoji 字符串判分，不按来源词条或位置；同 emoji 的多个选项都正确 |
| 用户两轮决定 | Boss 偶遇、醒目、刺激，可跳过；答对提供接下来 5 道普通题双倍奖励 |
| 用户本轮决定 | 持续收益与继续刷题的吸引力属于期望体验；不以一次性固定奖金替代 Buff |
| 用户现有玩法 | 10 分兑换 1 元；普通分数仍能兑换，不改变承诺 |
| 设计时的代码基线 | 本地直接打开 HTML 与同目录词库，无服务器；443 条记录等概率普通题，允许重复；按字母长度给 0.5、1、2 分 |
| 设计时的代码基线 | 积分通过 localStorage 保存；单页面事件循环；语音、计时器有异步回调；尚无历史、Boss、Buff |
| 当前词库 | 稳定词条 ID，图示可为空，存在同义图示、短语、缩写和特殊 speech 文本 |
| 本方案建议 | Buff 剩余次数跨关闭保留；生效期间不再触发 Boss，不叠加；不增加倒计时、扣分或付费随机机会 |
| 尚待实际观察 | 登场频率、长度范围和题型难度是否适合孩子；历史容量是否需要扩大 |

真实消费者只有孩子与家长、本地单页面游戏。设计按一个浏览器页面游玩；多设备同步、并发多标签合并、账号、后台统计不在本轮范围。localStorage 可以失败，不能宣称跨浏览器或搬动文件路径后仍一定保留。

## 游戏循环与登场

普通题完成 → 记录结果并结算 → 判断是否出现 Boss → 从历史生成合法题目 → 挑战成功获得 5 次双倍 → 完成 5 道普通题消耗 Buff → 恢复遇敌机会。

原型建议每个无 Buff 阶段随机抽取 8–12 作为距离下一次挑战的普通题完成数。用一个剩余计数表示距离，不同时维护完成数、概率累计和保底计数。Buff 生效期间暂停遇敌计数；Boss 结束后重新抽取。跳过、错误和语音故障均不会马上再生成一个 Boss。

只在当前题完整结束、庆祝完成之后生成下一题，不在输入过程中插入 Boss。候选不足时继续普通题；剩余计数保持为 0，每完成一道普通题重新检查资格，不空转或重新抽取隐藏等待。

Boss 使用独立背景、入场音效和大图标；短语音解释“挑战成功，接下来五题双倍！”并点名耳朵、退格、大勾和小伙伴。听音、改字、检查使用固定图示；求助面板中的学习／离开图卡只选择和说明，另点勾才执行。学习答案不获得本次 Buff。

Buff 显示为五颗能量标记及“本题 ×2”，每完成普通题消耗一颗。最后一次明确庆祝“双倍能量用完啦”。强调能量提升产出，保留用户期待的再生产刺激。退出不抹除未消费能量，也不设置限时领取或到期。

## 历史与最小数据

保存一个对象，不维护另一份持久化单词掌握表：

```js
{
  version: 1,
  score: 0,
  buffRemaining: 0,        // 0..5
  untilBoss: 10,           // 0..12；Buff 期间暂停
  history: [              // 按结束顺序，最多 100 条
    {
      wordId: 'cat-01',
      kind: 'normal',     // normal | image | partial | recall
      endedAt: 1790985600000,
      outcome: 'correct'  // correct | wrong | assisted | skipped | unavailable
    }
  ]
}
```

partial 记录额外保存实际 missingCount；其他题型不带该字段。例如 `{ wordId: 'cat-01', kind: 'partial', endedAt: 1790985600000, outcome: 'correct', missingCount: 1 }`。这是解释实际支架强度所用的一项题面事实；不保存遮挡位置、题面快照、按键流或冗余错按数。

只有已结束题写入历史；当前题、输入缓冲、图案位置和遮挡掩码在内存中。关闭未结束题不写结果、不消费 Buff、不算完成；重新打开从下一道普通题开始，不承诺恢复中途 Boss。endedAt 用于观察跨日表现，抽题顺序只用数组顺序，不依赖系统时钟。

普通题的 correct 是“在提示与逐字反馈下完成”，不能据此判定记忆掌握。Boss 的 correct 是首次有效提交正确，wrong 是首次有效提交错误；在求助面板确认学习答案，才以 assisted 结束奖励挑战。打开、选择与返回不写结果。重听完整英文不改变结果资格；额外显示、念出目标拼写或透露正确图案都是辅助学习，随后的跟练不再产生第二条结果。wrong、skipped、unavailable 分开记录，不把跳过与设备故障当成能力失败。

记录在结算处写一次；题目已结束后忽略重复点击、Enter 与过期语音回调。历史不是按键日志，不记录未提交的试写、退格和重听次数。

## 从历史动态选题

1. 取历史中 normal 且 correct 的记录；按 wordId 去重并查询当前正式词库，失效 ID 忽略。
2. 排除最后两道完成普通题的词，避免刚看过答案就立刻测试。例如 CAT→DOG→SUN 完成后，只有 CAT 通过间隔条件；若 CAT 又成为最新普通题，即使更早刷过，也暂时排除 CAT。
3. 为每个剩余词生成合法题型集合。partial/recall 要求无空格、3–8 个字母且没有特殊 speech；image 要求目标有图，并能找到至少一个不同且无已知冲突的图示。两个拼写题型同用一个长度带，不再按排序切掉“中间一半”。长词、短语可继续普通题；若有合法图示也可参与 image。
4. 过滤合法题型集合为空的词。先对剩余不同 wordId 等概率抽词，再对该词合法题型等概率抽取。同词刷 20 次仍只占一个候选位置；有三种题型的词也不会比只有两种题型的词更容易成为 Boss。
5. 没有合法候选时继续普通题。没有失败优先队列、上次 Boss 排除、逐词技能等级、晋级前提或独立持久化候选池。

冷启动依靠普通题自然积累；没有历史时不出现 Boss。这个模型自适应“近期实际接触了什么”，结果为后续能力调度留下依据；第一版不声称自动适应掌握程度。词离开 100 条窗口后，就不再是本方案的候选来源。三题型不依赖同词重复通关，因此稀疏历史也可以出现完整拼写。

## 三种挑战的语义

| 题型 | 提示与输入 | 合法题目条件 | 成功测到的能力 |
| --- | --- | --- | --- |
| 听音选图 image | 只播放目标英文，展示 3 个图案，点击后提交；不显示目标中文或英文 | 目标图必在选项内，允许同图多正确项，至少一个不同图作干扰；选完整字符串相同的图即正确 | 声音与现有图示的关联 |
| 部分拼写 partial | 整词英语、中文或图片；显示部分字母，只填写隐藏位置，允许退格后提交 | 单词长度 3–8；至少隐藏 1 个位置，且至少留 1 个字母 | 有支架的拼写回忆 |
| 完整拼写 recall | 整词英语、中文或图片；显示空格槽数量，26 个字母均可输入，允许退格后提交 | 单词长度 3–8；不含空格，speech 与拼写对象一致 | 有词义和长度线索的整词回忆 |

三种题型是不同能力的探测，选图成功不等于拼写过关。没有图示的词仍可用于部分和完整拼写，不能因为需要选图而丢弃整个词条。

partial 固定隐藏 floor(字母数 / 2) 个位置，位置随机且整题内不变，至少保留一个字母。隐藏位置即本题全部作答位置，输入缓冲按照未知格顺序填入，不要求重新输入已显示字母。保存实际 missingCount 便于解释不同长度词的支架强度。

三种题型直接开放，没有“先部分拼写赢几次才能完整拼写”的门槛。选图成功不改变拼写资格；无图词仍能参加 partial/recall。若真实试玩显示完整拼写过难，先调整集中配置的长度带或题型权重，明确这是难度调节，不把它包装为经过验证的能力估计。

选图题的标准答案是目标词 `illustration` 的完整原始字符串。候选来源 ID 只负责取材，不参与判分；按钮位置也不参与判分。每个按钮持有原始字符串，提交时 `selectedEmoji === targetEmoji`。不截首字符、不拆 code point、不移除变体选择符或 ZWJ，不从渲染后的文本反推答案。

最小生成过程：强制加入目标图；从正式词库中选择一个不同且无已知冲突的图；再从合法图示来源随机选一项，允许与目标或第二项相同；最后打乱位置。图示来源无需出现在孩子历史中，目标仍必须来自历史。不按 emoji 去重，不强制只留一个正确选项。第一额外槽必须不同，是本方案避免“全选都对”的原型约束，不是用户要求唯一正确答案。

例如听 BIKE，三个选项来自 BIKE 的 🚲、BICYCLE 的 🚲 和 DOG 的 🐶：点任意 🚲 都成功，点 🐶 才错误，交换按钮位置不改变结果。相同 emoji 的来源词可能不同，故成功只证明完成这道声音与图示关联题，不能据此判定懂得区分近义词或会拼写。

不同 emoji 却语义重叠的已知组合用小型无向冲突对排除，例如 HAT/CAP 的 🎩 与 🧢、BOY/CHILD 的 👦 与 🧒。冲突对直接用完整 emoji 字符串表达，只对与目标字符串不同的图生效；同图不会因词条来源不同而被排除。它只控制取材，不改写判分函数，也不建立语义标签体系或固定目标白名单。新增具体反例再补对，不宣称已自动消除全词库的语义歧义。

没有合法不同图时该词不出 image，尝试其合法拼写题型；两者都不可用则换历史中的其他词或继续普通题。实际设备看图、试听仍需验收，本轮只核对数据中的图示字符串。允许多正确项会降低部分题目的猜测难度，这是已接受玩法，不因此降低 Buff 或暗中去重。

输入尚未填满或没有选图时禁用提交，不把手误当成一次错误。首次有效提交错误即结束本次奖励挑战，显示正确答案并播放英文。之后可以跟着练一遍，不产生新的 Boss 成功结果或补发 Buff。可重听、编辑，但不能通过逐字判错试出答案，也不能通过反复提交图案获得“独立正确”。

## 奖励结算

Boss 独立成功只授予 buffRemaining = 5，不追加固定奖金，不消耗次数。三个题型奖励相同，题型由系统选择，孩子不通过自选最容易类型套取更高收益。

普通题完成时，先查看旧 buffRemaining；若大于 0，本题总奖励 = 原奖励 ×2，然后 buffRemaining 减一。score、Buff 消耗、历史追加、遇敌计数更新在同一个状态对象里计算后保存，避免分开保存导致刷新后重复消费或凭空丢失能量。

例：已有积分 10，Buff 剩余 1，完成 CAT 的原奖励 0.5；结算后为积分 11、Buff 0。下一题不再翻倍。失败与跳过 Boss 不扣钱，辅助学习不制造新的积分入口。

现有规则下，5 次双倍额外增加 2.5–10 分，即 0.25–1 元，取决于后续普通题长度。第一版保留这一再生产回报，不叠加随机倍率，不因通关率高自动减少奖励或提高兑换门槛。

## 本地保存与旧积分

新对象写入新的 localStorage key，例如 word-adventure-progress-v1。首次没有新对象时，按现有积分校验规则读取 word-adventure-score-v1，迁入 score，其余字段初始化；保留旧 key，不双写，也不支持旧页面与新页面同时更新分数。

同一次结算只对新 key 做一次 setItem，成功之前不宣称已持久化。写入失败仍可在内存继续玩，显示“这次进度没能保存，请保持页面打开”。这不是后台账本或强持久化承诺。

新对象无法解析或版本不支持时，不能静默退回旧积分并覆盖它；暂停计分游玩与自动保存，显示可读提示，保留原数据供家长处理。加载后的非法历史项可忽略，核心积分、Buff 或遇敌计数非法则不自动重置。当前没有服务端、防篡改、多人、多标签一致性需求，不引入事务日志、锁、修复框架或通用事件框架。

## 与现有代码的接入边界

普通题保留 drawWord 等概率抽取、字母名朗读、有限键盘和逐字反馈。Boss 是当前题目的另一种模式，不复制词库、不为同词建立多条难度词条。

startWord 或较小的下一题入口负责先选 normal/Boss，再派发到相应渲染和输入分支；无需引入插件注册表、调度服务或独立游戏引擎。

Boss 不沿用 showSpelling=false 作为全部实现：playPrompt 仍念字母；renderAudioState 会显示朗读文本；chooseLetters 暴露目标字母集合；inputLetter 按位阻止错误。Boss 须逐处收口：

- 音频只念完整词，状态文字只显示“正在读”“再听一次”，不回显目标英文。
- 选图的标题、中文解释、图案 aria-label 和位置不得泄露正确选项；相同 emoji 使用相同可访问名称（从该 emoji 的一个稳定代表词取中文），不显示来源英文或把位置标作正确；语音读目标英文时不回显。
- 拼写的未知格不在 aria-label 或其他可见提示中含目标字母；26 键均开放，悬停可读单个键名，不能按目标位置自动读答案。
- 输入缓冲与答案比较分开，首次提交时统一判定；部分拼写只把未知位置映射回完整答案。
- 语音取消、页面失焦、重听和完成后自动下一题沿用现有 generation/complete 防护，避免旧回调跳过 Boss 或二次结算。

每题只有一个内存资格 heardTarget，初值 false。当前题目标英文完整播放成功结束，且回调 generation 匹配、没有取消或故障，才置为 true，直到本题结束不撤销。heardTarget 为 false 时禁用提交；中文、图片和部分字母不能替代听音资格。

首次手势限制、播放错误或超时允许重听，也可从故障提示打开求助，再确认去普通关并结束为 unavailable；浏览器明确不支持语音时自动结束 unavailable。正常跳过记 skipped；这两个结果结算后都直接进入普通题，不展示或朗读 Boss 答案。已经有一次完整播放后，重听失败只提示，不撤销资格，也不改成 unavailable。主动取消、失焦或切换页面不记能力失败；未完整播放则等待重听。旧题音频回调不能授予新题资格。

浏览器播放结束事件只是程序可观察证据，不保证现实中声音可听见；真实试听仍是设备验收的一部分。不持久化音频资格或音频事件流。

## 验证与实现顺序

最小纵向切片：历史与统一结算 → 从历史选合法词 → 完整拼写 Boss → 五次双倍显示、消耗与保存。该切片先验证“凭记忆作答换来后续收益”的核心循环。随后加入部分拼写，最后接入按 emoji 判分的听音选图。最终功能仍覆盖三类题，不把阶段性交付写成全部完成。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 冷启动与刚练过的词 | 不考没完成过普通题的词；不考最后两道普通题的词 |
| 历史 101 条与重复词 | 只留最新 100 条；同词不会因频次占更多抽签位置 |
| 长词、短语、特殊 speech、无图词 | 合法降级或暂不考；无图词仍能出拼写题 |
| Boss 逐字试错与答案泄露审计 | 不提供目标拼写语音/字幕，不按位阻止错字，首次错误不发 Buff |
| 多正确选图与来源位置 | 听 BIKE，BIKE/BICYCLE 两个 🚲 都正确；🐶 错误；换位置不影响判分 |
| 图示序列与已知冲突 | 保留完整 VS16/ZWJ；🎩/🧢 的已知冲突不共题；同图不因来源排除 |
| 全正确候选 | 始终保留至少一个不同图；无法生成时改型或回普通题，不无限重抽 |
| 成功、辅助、跳过、故障 | 只有有效首次独立成功发 5 次 Buff；其余结果分开记录；不完整输入不会终结 |
| 首次播放失败与重听失败 | 未听完前不能提交，可重听；已听完后的重听失败不撤销提交资格 |
| 稀疏历史与题型 | 同词无 Boss 历史也能出完整拼写；先抽词再抽型，不按题型数增加词概率 |
| 第五次双倍与连续提交 | 第五次仍翻倍，第六次恢复；同题只结算一次 |
| 关闭、重开、保存失败、旧积分 | 未消费 Buff 保留；未结束 Boss 不发奖励；旧积分迁入；保存失败不声称已保存 |
| 失焦与旧语音回调 | 不中途换题、不多扣次数、不重复记录 |

首次实现后用真实浏览器本地打开验收，实际试听目标设备声音与看图辨义。算法测试可固定历史和随机数，检验筛选与结算；不承诺游戏确定性回放。

试运行观察：每种题型首次无提示正确率、真实错误比例、跳过与语音失败比例；跨日再次出现的同词表现；普通题完成数、Buff 使用数和收入。日志只能反映窗口内表现，没有跨日样本时明确显示“样本不足”，不把普通题刷得多命名为“已掌握”。不必先建设家长仪表盘，开发期从保存对象检查即可。

## 已落地的实现与验收

直接打开 [word-adventure.html](../word-adventure.html) 即可游玩；同目录必须保留 [词库](../word-adventure-words.js) 和新增的 [游戏规则](../word-adventure-game.js)。游戏运行不需要 Node.js、服务器或构建。

规则文件集中提供 `OPTIONS`、`createProgress`、`parseProgress`、`bossCandidates`、`createBoss`、`isBossAnswerCorrect` 和 `settle`。HTML 负责渲染、作答缓冲、完整听音资格与重复结算防护。未增加掌握表、家长仪表盘、额外复习队列或生产调试入口。拼写候选保守排除所有显式 `speech` 覆盖；选图保留原始 emoji 字符串和多正确位置。

普通题庆祝后自动继续；Boss 正确、错误或辅助学习后，使用带图示的“去普通关”或“带着双倍能量出发”；正常跳过与听音故障则直接普通题。拼写挑战错误或学习答案后，可以点击写字卡“跟着拼一遍”，这次跟练不另记历史、不增加积分或 Buff。庆祝语音期间下一题按钮暂时禁用，语音完成、失败或取消后恢复。重新打开总从普通题开始；历史和剩余能量保留。

新存档使用 `word-adventure-progress-v1`，保留旧积分 key 且不双写。新存档核心损坏或无法读取时暂停游戏，不覆盖原数据；旧 key 的非法分值按原校验规则视作 0。写入失败时继续内存游玩并显示保存失败提示。

## 延后与重新考虑的触发条件

| 延后事项 | 重新考虑的证据 |
| --- | --- |
| 能力档位与按正确率调整题型 | 出现足够重复挑战样本，且试玩确实需要自动调节难度 |
| 错词优先与额外 Boss 冷却 | 观察到错词长期未复习或同词连续挑战影响体验 |
| 长期每词能力档案和间隔复习算法 | 100 条窗口频繁丢失有用证据，或家长明确需要长期学习统计 |
| 加权普通题复习 | 观察到 Boss 回忆失败但等概率普通题长时间不再接触同词 |
| 图示语义标签体系或新增插画 | 小型已知冲突对不足以处理实际反例，且选图题确实值得扩大覆盖 |
| 更复杂的收益、叠加 Buff、随机倍率 | 五次双倍循环已验证，用户另行选择新的玩法 |
| 多标签、多设备、服务端保存 | 出现真实消费者与一致性需求 |

本方案采用已练词的动态回忆挑战，并保留持续收益奖励。它不声称能保证长期记忆或必然形成上瘾；学习增益和游戏吸引力分别用实际行为验证。
