# 动态 Boss 设计审查记录

日期：2026 年 10 月 3 日。范围：设计文档与当前代码的只读核对；本轮只修改文档，没有实现功能。最终行为契约以 [设计方案](boss-design.md) 为准，本记录说明裁决依据，不是第二份运行时规范。

最小模型：最近 100 条已结束题目是取材来源；先抽一个有合法题型的历史词，再抽题型；有效首次提交成功授予五次双倍。选图提交的完整 emoji 字符串与目标相等就正确，多个相同图选项全部接受。

## 方法与证据

采用 dialectical-simplification：需求怀疑者、最小架构师、语义守护者分别完整阅读草案，独立提交第一轮 findings；第二轮交换最强对立主张；第三轮仅复核用户新提出的 emoji 判分规则。主线程核对实际源码与词库，并裁决。没有用投票代替证据，也没有让审查者修改文件。

证据优先序：用户最新决定 → 当前游戏及数据 → 具体失败轨迹 → 草案建议。各审查意见来自同一草案，不算独立产品需求。此次没有新增文献结论，学习效果仍待试玩验证。

当前源码核对：

- `drawWord` 对 443 条词汇等概率抽取；History 100 的每词 Boss 证据会稀疏，不能假设每词频繁复考。
- `playPrompt` 仍逐字读拼写；`renderAudioState` 显示朗读文本；`inputLetter` 只接受当前位置的正确字母；`chooseLetters` 只开放目标字母及少量干扰。这些行为不能直接当成默写。
- 正式数据 443 条，其中 395 条满足无空格、3–8 个字母且无特殊 speech 的拼写候选格式；189 条有非空图示。这些数量不是 History 中当前可用候选数，也不是视觉验收结果。
- 特殊 speech 有 TV、MR、MRS、MS、PE；第一版拼写 Boss 保守排除全部带 speech 的条目，普通题不受影响。
- BIKE/BICYCLE 共用 🚲，BALL/FOOTBALL 共用 ⚽，HELLO/HI/BYE 等共用 👋；用户新规则把同图多正确明确定义为合法，而非数据错误。
- HAT/CAP 分别为 🎩/🧢，BOY/CHILD 分别为 👦/🧒。这些不同字符串的语义重叠不由字符串相等规则自动解决，最小处理是已知冲突对。

## 裁决

| 评估项 | 结论 | 依据与最小替代 |
| --- | --- | --- |
| History 100 动态取材 | keep | 用户明确决定；normal 完成证明接触过，不能推导已掌握 |
| 三种题型与五次双倍 | keep | 用户明确决定；不改成固定奖金或人工固定学习池 |
| 每词两次 partial 才开放 recall | defer | 100 条记录中 90 个不同普通词、10 个不同 partial 时，完整拼写一直不开；直接开放全部合法型 |
| 最近一次成功即晋级的替代 | defer | 修复因果冲突但仍依赖同词重考；当前没有必须技能分档的用户要求 |
| 长度排序的中间一半 | simplify | 同长度词仍会按数组位置裁掉一半；只保留一个可配置长度带 |
| 错词一次复习优先与上次 Boss 排除 | defer | “一次”消费未定义、与冷却冲突；已练词等概率足够形成当前循环 |
| 持久化技能等级、候选缓存 | delete | History 已是取材权威，无当前消费者需要第二份状态 |
| Boss inputErrors、usedHint | merge | 用 correct/wrong/assisted/skipped/unavailable 表达唯一结果；看答案直接辅助终结 |
| partial 的实际 missingCount | keep | 主线程保留一个实际题面事实用于解释支架强度，不保存完整掩码或按键日志 |
| 选图必须单一正确位置 | delete | 被用户最新决定推翻：完整 emoji 相同即可，位置与来源不参与判分 |
| 人工三词图组或固定素材白名单 | delete | 由单正确选项假设派生，现可从正式图示数据取材，无需限定目标池 |
| 至少一个不同 emoji 干扰 | keep | 原型难度约束；全选皆对没有选择意义，仍允许两格都正确 |
| 不同图的已知语义冲突对 | keep | 🎩/🧢 都可能被理解为帽子，已知反例需避免；不引入语义本体 |
| 额外立即奖金 | delete | 用户明确拒绝；成功只产生后续收益 Buff |
| 首次整题提交、输入缓冲 | keep | 复用逐字判错会允许试按枚举答案并取得 Buff |
| 本题完整播放资格 | keep | 播放尚未成功时不得靠中文猜题先结算；重听故障不能撤销先前资格 |
| 同一对象保存积分、Buff、历史 | keep | 分开写入可能使刷新后重复双倍或消耗次数却未得分 |
| 遇敌概率累计与多套保底时钟 | simplify | 一个直到下次 Boss 的普通题剩余计数即可，Buff 期间暂停 |
| 多设备同步、日志事务、通用游戏框架 | defer | 本地单页面，没有当前消费者；有真实需求再设计 |

删去了逐词解锁、中位排名、失败优先和人工图组四套出题机制；结果表示由 outcome 加 usedHint/inputErrors 合并为一个 outcome。没有以减少字段为理由删除用户决定的奖励次数、答题因果或听音资格。

## 交叉质疑中的修正

第二轮中，最小架构师撤回“最近一次成功晋级”门控建议，语义守护者撤回“必须按时序折叠技能档位”的建议。后者原本正确修复旧成功覆盖新失败的问题，但删除非必需档位后，该问题与修复一起消失。需求怀疑者明确修正措辞：单次晋级并非逻辑上不可达，只是在当前稀疏节奏下可能长期不出现，尚未实测频率。

第三轮中三位审查者均接受用户新的判分法则，撤回“重复图不合法”“只允许一个正确选项”“必须人工图组”的旧建议。重复正确图降低猜测难度是用户接受的玩法，不以测试纯度为由去重、减奖励或改回位置判分。

partial 是否需要 missingCount 没有完全一致：最小架构师指出固定规则下可由词长推导；语义守护者主张保存实际支架强度。主线程保留这一个字段，理由是开发期确实要解释不同题面下的正确率，而用户明确需要答题记录作为数据基础。该分歧不影响抽题、判分或奖励，未制造额外一轮讨论来要求一致。

## 不可删除的具体轨迹

1. 普通题完成 CAT、DOG、SUN；CAT 才满足“隔两道普通题”的候选条件。只有打开或未完成 CAT，不足以入池。
2. 听 BIKE，选项为 🚲、🚲、🐶；任意 🚲 都成功。交换位置或换成 BICYCLE 来源不改变正确性。
3. 听 HAT，若出现 🎩、🧢、🐶，生成时排除已知冲突 🧢；不把 🧢 自动视为相同字符串，不惩罚孩子对已知歧义的合理理解。
4. 未播放成功时提交禁用；完整播放一次后，第二次重听失败，只提示故障，仍可提交。
5. 首次错答结束为 wrong，显示答案后跟练正确不能补发 Buff。点击看答案先结束为 assisted，也不能二次记题。
6. 普通题原奖励 0.5、Buff 剩余 1，结算为加 1 分、剩余 0；重复提交不结算；下一普通题恢复原奖励。
7. 保存积分成功但另存 Buff 失败会制造额外双倍，因此一个对象一次写入；坏新对象也不能退回陈旧旧 key 并覆盖新进度。

## 实施边界与未验证事项

当前没有需要用户再做技术决策的阻塞项。默认 History 100、3–8 字母、8–12 道普通题间隔、五题 Buff 跨关闭保存等，均作为可调整的原型方案；其中数值与退出规则未经过孩子试玩验证。

最小实现顺序：完整拼写与奖励循环纵向接通 → 部分拼写 → emoji 选图。关键验证是历史来源与概率顺序、首次提交、完整音频资格、同 emoji 多选项一致判分、第五次双倍、保存与迁入。没有代码改动，不能声称这些运行行为已通过测试。

长期掌握模型、错词复习权重和自动能力调节均写明重新启用条件。100 条窗口没有某词跨日重复样本时，不输出“已掌握”结论。
